# 程序可用性实测与"需借鉴开源"环节定位

> 目标：实际检测「知枝 / 知识树 Agent」当前能否正常工作，并对照两个开源项目（`mind-map-mcp`、`SparkNoteAI`）明确**哪些部分需要借鉴**、哪些已经够用。
> 实测时间：2026-08-16 ｜ 环境：uv 0.12.3 / Python 3.13 / Node 22 / Windows

---

## 一、实测方法（都是真跑，不是看代码猜）

1. **依赖与启动**：`uv sync --locked --group dev` 装好 workspace；用项目自带 `uv run` 运行。
2. **离线生成引擎实测**：写脚本驱动项目内置的 `HeuristicConceptExtractor`（把 `#` 标题当概念），走完整 `文本 → AiDraft → GraphPatch → preview_graph_patch` 链路（**不依赖 DeepSeek key**）。
3. **测试套件**：运行 `tests/integration/test_ai_draft_api.py` + `tests/contract/test_graph_contracts.py`（共 **27 个用例**）。
4. **真机 HTTP**：用 `apps.desktop.launcher --no-window` 真正起服务（端口 8011，临时 data-root），用 curl 打 health / 建工作区 / ai-draft / 取图 四个接口。

## 二、实测结论：哪些部分**能正常工作**（已验证）

| 能力 | 验证方式 | 结果 |
|---|---|---|
| 桌面 sidecar 启动 + HTTP 服务 | curl `/api/health` | ✅ `200 {"status":"ok"}` |
| 工作区创建与落库 | POST `/api/workspaces` + GET `/graph` | ✅ 新建工作区并持久化（取回"实测工作区"概念） |
| AI 草案**引擎**（文本→概念→关系→GraphPatch） | 离线脚本实测 | ✅ 一条 7 标题笔记 → **7 概念 + 6 关系 → 20 个 GraphPatch 操作**，预览状态 `requires_confirmation` |
| 完整生成→确认→入库闭环 | 集成测试 `test_ai_draft_api.py` | ✅ 27 个相关用例全部通过 |
| `GraphPatch.operations.maxItems` 上限修复 | 契约测试（含 150 操作用例） | ✅ 已放宽到 **5000**，大草案被接受、越界仍拒 |
| AI 无 key 时**安全 fail-closed** | POST `/ai-draft`（未配 key） | ✅ 返回 **503 `ai_not_available`**，`/api/settings/ai` 显示 `configured:false` |

**结论：你程序的核心逻辑（笔记编辑外壳、AI 草案抽取引擎、确定性契约校验、确认入库闭环、桌面 sidecar）都是能正常发挥作用的。** 之前"AI 没有任何实际作用"不是引擎坏了，而是两个外部卡点（见第三节）。

## 三、实测暴露的限制（为什么你之前觉得"没用"）

1. **AI 必须配置 DeepSeek key 才启用**（接口 `POST /api/settings/ai`）。没配 key → `ai-draft` 直接 503，表现就是"点了没反应"。这是最常见的"没实际作用"原因。
2. **你跑的是「冻结 exe」，但 maxitems 修复只在源码里**。`uv sync`/源码启动时修复已生效；但上一轮我们把 `maxItems` 100→5000 改在源码+契约里，**必须重新 `pyinstaller` 打包 exe 并重新分发**，你手上的 exe 仍是旧的 100 上限——短文件也触顶、直接 fail-closed。
3. 离线引擎用的是 `#` 标题抽取（演示级）。**真正的 AI 抽取依赖 DeepSeek 返回结构化 JSON**，需要 key + 网络。

## 四、哪个部分需要借鉴开源项目（对照实测，已逐项确认缺口）

| 环节 | 你程序现状（实测） | 缺口？ | 该借鉴谁 / 怎么借鉴 |
|---|---|---|---|
| 桌面 UI / 手动笔记编辑 | ✅ 已工作（pywebview + FastAPI） | 否 | 无需借鉴 |
| AI 草案抽取引擎 | ✅ 已工作（离线验证通过） | 否 | 你们的 `ai_draft` 比 `mind-map-mcp` 的 markdown 树更丰富，无需借鉴 |
| 契约 / 确定性校验 | ✅ 已工作（maxitems 已修） | 否 | 你们自研契约已领先 |
| **应用内置 MCP server** | ❌ **全代码库零 MCP 实现**（grep `mcp.server`/`FastMCP`/`stdio_server` 均无命中） | **是** | 借鉴 `mind-map-mcp` 的**传输骨架**（stdio/sse/streamable-http、tool 注册、Windows UTF-8、HTTP 懒加载）。⚠️ 该项目**无 LICENSE（默认保留所有权利）**，只能学思路、**自研等效实现**，不能直接 copy |
| **脑图 PNG 导出** | ❌ 无（grep 全库无 matplotlib/PIL 渲染导出，仅有图标生成） | **是** | 借鉴 `mind-map-mcp` 的 `_parse_markdown_to_tree` + `matplotlib+PIL` 渲染层（约 200 行，自研成本极低）；把它改成接收你们的 concept/edge 树而非 markdown |
| **前端思维导图可视化** | ❌ 前端依赖仅 `react` + `pdfjs-dist`，**无任何图可视化库**（grep react-flow/cytoscape/d3/force-graph 均无） | **是** | 借鉴 `SparkNoteAI` 的"概念→力导向图"**思路**，但**不可**用其 AGPL 的 `react-force-graph`；改用 MIT/Apache 库（React Flow / Cytoscape.js） |

> 一句话：你程序"**生成侧**"已经能打（不用抄）；真正缺的是"**暴露侧**"——把能力通过 MCP 暴露出去（借鉴 mind-map-mcp）、把图导出成图片（借鉴其渲染层）、以及把图在 UI 里画出来（借鉴 SparkNoteAI 思路、换 MIT 库）。

## 五、建议行动清单（按优先级）

1. **【立即】重建 exe**：你手上的 exe 仍是旧 `maxItems=100`，必须先 `pyinstaller` 重新打包（参考 `apps/desktop/build.spec` + `WORK-2026-035`），否则 maxitems 修复对你无效。
2. **【立即】确认 AI 已配 key**：在应用里 `POST /api/settings/ai` 填入 DeepSeek key；否则 `ai-draft` 永远 503。
3. **【本期】自研内置 MCP server**：参考 `mind-map-mcp` 传输骨架，用 FastMCP 暴露 `preview_draft` / `apply_patch` / `read_note` / `generate_mindmap`，全部走你们现有 `GraphPatch` 校验（延续"AI 绝不直写库"约束）。因对方无 license，**自研不 fork**。
4. **【本期】自研脑图 PNG 导出**：把 `mind-map-mcp` 的 matplotlib+PIL 渲染改写成接收 concept/edge 树（非 markdown）的 `generate_mindmap` tool。
5. **【下期】前端可视化**：引入 React Flow 或 Cytoscape.js（MIT）渲染知识树/思维导图，替代目前仅 PDF/文本的现状。

## 六、实测原始证据

- 集成+契约测试：`27 passed in 8.34s`
- 离线引擎输出：`抽取概念数: 7 / 抽取关系数: 6 / GraphPatch 操作数: 20 / 预览状态: requires_confirmation`
- Live HTTP：
  - `GET /api/health` → `200 {"status":"ok"}`
  - `POST /api/workspaces {"name":"实测工作区"}` → `200` 返回新 workspace id
  - `GET /api/settings/ai` → `200 {"configured":false,"enabled":false}`
  - `POST /api/workspaces/{id}/ai-draft` → `503 {"code":"ai_not_available"}`（无 key，正确 fail-closed）
  - `GET /api/workspaces/{id}/graph` → `200` 含刚建的概念

*注：上述 live 服务以 `--no-window` 跑在临时 data-root、仅绑定 127.0.0.1:8011，测试后已尝试关闭。*
